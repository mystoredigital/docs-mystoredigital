Filosofía: Files over Apps

El 23 de julio 2026 adoptamos la metodología del CEO de Obsidian, Steph Ango, basada en dos principios que cambian la forma de organizar el conocimiento:

Principio 1 — Files over Apps

Implementado

El conocimiento vive en archivos markdown que tú controlas. No en bases de datos de ninguna aplicación. Si cambias de herramienta mañana, todo sigue contigo. Obsidian es un lector de archivos, no un custodio de tus datos.

Principio 2 — Estructura bottom-up

Implementado

La estructura emerge de propiedades YAML y wikilinks, no se impone desde arriba con carpetas. Las carpetas son contenedores de tipos, no de temas. La barra lateral de carpetas deja de ser la navegación principal: la reemplazan las Obsidian Bases.

Referencia. Vault original de Steph Ango disponible en stephango.com/vault y en GitHub: kepano/kepano-obsidian.

Obsidian Bases — vistas de base de datos

Obsidian Bases es una capa de base de datos nativa (sin plugins externos) que filtra y visualiza notas según sus propiedades YAML. El campo tipo: en el frontmatter de cada nota es la llave que Bases usa para filtrar.

Requisito. Para que Bases funcione, cada nota necesita tipo: en el frontmatter. Sin ese campo, la nota es invisible para las vistas.

Cómo crear una nueva Base View
  1. En el explorador de Obsidian, click derecho en la carpeta destino → New file
  2. Nombre con extensión .base — ej: 📊 Mi Vista.base. La extensión activa el modo automáticamente.
  3. Configurar filtros en el YAML del archivo: 
    filters:
  and:
    - tipo.eq("clipping")
    - fuente.eq("YouTube")
  4. Agregar propiedades a mostrar y crear tabs (views) con distintos filtros u ordenamientos.

Ver BASES.md en el repo para la sintaxis completa con ejemplos.

Templates actualizados

Tres templates actualizados o creados. Todos incluyen tipo: y propiedades como listas (no texto) para permitir múltiples valores y filtrado en Bases.

plantilla CAPTURA.md — Clippings Actualizado

Para YouTube, artículos, posts de redes, herramientas — cualquier contenido de terceros.

---
tipo: clipping
fuente: ""          # YouTube / LinkedIn / Web / Instagram
url: ""
autor: []
fecha_captura: YYYY-MM-DD
categoria:
  - "[[Categoría]]"
temas: []
personas: []
tags:
  - captura
---
YouTube. Para videos de YouTube usar el skill youtube-capture de ClaudeClaw — crea la nota automáticamente con transcript, propiedades ricas y wikilinks.
plantilla LIBRO.md — Biblioteca personal Actualizado

Para libros en cualquier estado: pendiente, leyendo, leído.

---
tipo: libro
categoria:
  - "[[Libros]]"
titulo: ""
autor: []
estado: pendiente   # pendiente | leyendo | leído
rating:             # 1-5 al terminar
año:
paginas:
temas: []
personas: []
conceptos: []
---

La Base View de Libros filtra por estado: para mostrar "Pendientes", "Leyendo ahora" y "Leídos" en tabs separados.

plantilla CONTACTO.md — CRM personal Nuevo

Para cualquier persona en la red: negocio, proveedor, colaborador, familia.

---
tipo: contacto
categoria:
  - "[[Contactos]]"
nombre: ""
empresa: []
relacion: ""        # negocio | familia | proveedor | colaborador
telefono: ""
email: ""
cumpleanos: ""      # YYYY-MM-DD — Bases calcula edad automáticamente
ultimo_contacto: "" # YYYY-MM-DD
ciudad: ""
tags:
  - contacto
---

La propiedad cumpleanos: en formato ISO permite que la Base View de Contactos calcule la edad con una fórmula nativa.

Regla de wikilinks (obligatoria)

En el cuerpo de cualquier nota, usar [[dobles corchetes]] para conectar con personas, libros, conceptos y proyectos — aunque la nota destino no exista aún. Estos unresolved links son intencionales: aparecen grises en el grafo y se activan cuando creas la nota destino.

Agent Memory en Obsidian

La carpeta 223 - 🤖 AGENT MEMORY es la memoria persistente del agente IA Sam entre sesiones. En lugar de guardar contexto en una base de datos interna opaca, vive en archivos markdown que tú controlas, editas y owns.

Principio
Files over Apps aplicado a la IA — si el agente muere o migras, el contexto sobrevive
Formato
Markdown plano, editable desde Obsidian directamente
Soberanía
Tú editas → el agente respeta como fuente de verdad en la próxima sesión
ArchivoContenidoQuién lo actualiza
CONTEXTO.mdPerfil del usuario, proyectos, stack, preferenciasSam + Yoany
DECISIONES.mdLog de decisiones técnicas y de negocioSam al final de sesión
PENDIENTES.mdTareas activas, blockers, completadosSam + Yoany
SKILLS_ACTIVOS.mdSkills configurados y automatizacionesSam al configurar
PROTOCOLO.mdReglas de cómo funciona el sistemaYoany (define las reglas)
Antes vs ahora. Antes: Sam guardaba contexto en SQLite (caja negra). Ahora: todo en Obsidian markdown. Cambia de agente, de app, o de máquina — el contexto sobrevive en tus archivos.
